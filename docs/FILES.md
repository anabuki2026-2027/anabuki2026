## 1. 先に知っておく言葉

このページによく出てくる言葉です。

| 言葉 | 意味 |
| --- | --- |
| **CakePHP** | このアプリを作るための「土台」。ログインやデータベースなど、よく使う機能が最初から用意されている。 |
| **PHP** | このアプリを書いているプログラミング言語。 |
| **データベース** | 会員の情報や投稿など、アプリのデータをしまっておく「表（Excel のようなもの）」の集まり。 |
| **Model（モデル）** | データベースとやりとりする係。データを出し入れする。 |
| **View（ビュー）** | 画面の係。ブラウザに表示される見た目を作る。 |
| **Controller（コントローラー）** | まとめ役。「どのデータを使って、どの画面を出すか」を決める。 |
| **URL** | ブラウザの上に表示されるアドレス。例：`http://localhost/anabuki2026/users` |
| **ライブラリ（部品）** | 他の人（世界のどこかにいるエンジニア）が作ってくれた、便利なプログラムのかたまり。 |
| **ログ** | アプリの「日記」。エラーが起きたときの記録が残る。 |
| **キャッシュ** | 速く動かすために、一時的にとっておくデータ。 |

Model・View・Controller の 3 つの関係は、レストランにたとえると分かりやすいです。

| 係 | レストランだと | このアプリだと |
| --- | --- | --- |
| Controller | 注文を受ける店員 | 「この URL が開かれたら、これをする」と決める |
| Model | 冷蔵庫から材料を出す人 | データベースからデータを持ってくる |
| View | お皿に盛り付ける人 | データを見やすい画面にする |

## 2. チームと担当ファイル

### チーム一覧

| チーム | 担当 | 主にさわる場所 |
| --- | --- | --- |
| **A** | 全体の統括・管理 | `config/`、`composer.json`、`.github/`、`src/Application.php` |
| **B** | Model | `src/Model/` |
| **C** | View | `templates/`、`src/View/` |
| **D** | Controller | `src/Controller/` |
| **E** | デザイン | `webroot/css/`、`webroot/img/`、`webroot/font/` |
| **F** | DB（データベース） | `config/Migrations/`、`config/Seeds/`（どちらもこれから作る） |
| **G** | テスト | `tests/` |

### 担当欄の見かた

このページの表の一番右の列には、そのファイルを**編集するチーム**を書いています。

| 書き方 | 意味 |
| --- | --- |
| `A` など | そのチームが編集する |
| `C・E` など | 2 つのチームが協力して編集する。さわる前にもう一方のチームに声をかける |
| `全員` | 全チームが、自分のパソコンの分だけ編集する |
| 👀 | 見るだけ。どのチームも基本的に編集しない（変えたいときは A に相談） |
| 🚫 | 絶対に編集しない（自動で作られる・上書きされる） |

> 自分のチームの担当でないファイルを変えたいときは、**そのチームに相談**してください。
> 担当がわからないときは A チームに聞いてください。

### チームどうしのつながり

1 つの機能（たとえば「会員登録」）を作るときは、だいたい次の順番でバトンをわたします。

```text
F（DB）       … データベースに「会員」の表を作る
   ↓
B（Model）    … 「会員」の表を読み書きするプログラムを作る
   ↓
D（Controller）… 「/users/add が開かれたら、会員を登録する」処理を作る
   ↓
C（View）     … 登録フォームの画面を作る
   ↓
E（デザイン）  … 画面の見た目（色・配置・画像）を整える
   ↓
G（テスト）    … ちゃんと動くかをチェックする
```

A チームは、この流れ全体を見守り、設定やルールを管理します。

## 3. ページが表示されるまでの流れ

ブラウザでアプリを開くと、次の順番でファイルが使われます。
上から下へ、バトンをわたすように進みます。右側は、その場所を担当するチームです。

```text
① ブラウザで URL を開く
        ↓
② webroot/index.php        … アプリの「玄関」。すべてここから入る         （🚫）
        ↓
③ config/ の設定ファイル     … アプリの設定を読み込む                     （A）
        ↓
④ src/Application.php      … 安全チェックなどをする                     （A）
        ↓
⑤ config/routes.php        … URL を見て「どの Controller の出番か」を決める（A・D）
        ↓
⑥ src/Controller/          … Controller が仕事をする                    （D）
        ↓                     必要なら src/Model/ でデータを持ってくる      （B）
        ↓                     そのデータはデータベースに入っている          （F）
⑦ templates/               … 画面（HTML）を作る                         （C）
        ↓                     webroot/css/ で見た目を整える               （E）
⑧ ブラウザに画面が表示される
```

## 4. 一番上にあるファイル

`anabuki2026` フォルダを開いてすぐの場所にあるファイルです。

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `README.md` | アプリの説明書。準備のしかたや、毎日の作業の流れが書いてある。 | A |
| `index.php` | まちがって一番上の場所が開かれたときに、本当の玄関（`webroot/index.php`）へ案内するファイル。 | 🚫 |
| `.htaccess` | XAMPP（Apache）への指示書。「来た人を全員 `webroot` フォルダへ案内して」と書いてある。 | 🚫 |
| `composer.json` | このアプリが使う部品（ライブラリ）の「買い物リスト」。 | A |
| `composer.lock` | 実際に使っている部品の「レシート」。バージョンまで正確に記録されているので、全員が同じ部品を使える。手で書きかえない（A がコマンドで更新する）。 | 🚫 |
| `.editorconfig` | VS Code などのエディタに「字下げはスペース 4 つ」などのルールを教えるファイル。 | 🚫 |
| `.gitattributes` | Git への細かい指示（改行のしかた、画像の扱い方など）。 | 🚫 |
| `.gitignore` | 「GitHub に送らないファイル」のリスト。パスワードが入ったファイルなどを守る。 | A |
| `phpcs.xml` | 「コードの書き方がルールどおりか」をチェックする道具の設定。 | A |
| `phpstan.neon` | 「プログラムにミスがないか」を、動かす前にチェックする道具の設定。 | A |
| `psalm.xml` | `phpstan.neon` と同じ種類の、ミスを探す道具の設定。 | A |
| `phpunit.xml.dist` | 自動チェック（テスト）の設定。 | G |

## 5. config フォルダ（設定）

**ひとことで：アプリの設定がまとまっている場所。**
基本的に A チームが管理します。F チームはデータベースの表を作るファイルをここに置きます。

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `app.php` | アプリ全体の基本の設定。時間（日本時間など）、エラーの出し方、メールの送り方などを決めている。全員共通。 | A |
| `app_local.php` | **自分のパソコン専用**の設定。データベースのパスワードなどが入っている。秘密の情報があるので、GitHub には送らない。 | 全員 |
| `app_local.example.php` | `app_local.php` の「見本」。最初の準備のときに、これをもとに `app_local.php` が自動で作られる。 | A |
| `.env.example` | 別の書き方で設定をするときの「見本」。今は使っていない。 | A |
| `bootstrap.php` | アプリが動き出すときに一番最初に読まれるファイル。上の設定ファイルを読み込んで、準備をする。 | A |
| `paths.php` | 「`webroot` フォルダはここ」「`logs` フォルダはここ」のように、フォルダの場所を決めている。 | 🚫 |
| `plugins.php` | 追加機能（プラグイン）の一覧。下の 3 つが入っている。 | A |
| `routes.php` | **URL の案内表**。「この URL が開かれたら、この Controller の出番」と決めている。新しい URL を作りたいときは、D が A に相談する。 | A・D |
| `schema/i18n.sql` | 翻訳機能を使うときに必要なデータベースの表。今は使っていない。 | 👀 |
| `schema/sessions.sql` | ログイン状態をデータベースに保存するときに必要な表。今は使っていない。 | 👀 |
| `Migrations/`（まだない） | **データベースの表を作る・変えるためのファイル**を入れるフォルダ。`bin/cake bake migration ○○` を実行すると自動で作られる。 | F |
| `Seeds/`（まだない） | データベースに最初から入れておくデータ（ためしの会員など）を書くフォルダ。 | F |

`plugins.php` に入っている追加機能：

- **DebugKit**：開発中、画面の右下に出てくる小さなアイコン。押すと「どんな処理が動いたか」が見られる。
- **Bake（ベイク）**：コマンドを 1 行打つだけで、Controller や Model のファイルを自動で作ってくれる。
- **Migrations（マイグレーション）**：データベースの表を、プログラムで作ったり変えたりできる。F チームが使う。

`routes.php` の案内のしかた：

| 開いた URL | 表示されるもの |
| --- | --- |
| `/`（トップ） | `templates/Pages/home.php` |
| `/pages/○○` | `templates/Pages/○○.php` |
| `/users/add` など | `UsersController` の `add` という処理 |

## 6. src フォルダ（プログラム）

**ひとことで：アプリの「頭脳」。PHP のプログラムが入っている場所。**

### src フォルダの一番上

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `Application.php` | アプリの「本部」。ページを開いたとき、Controller に届く前に「安全チェック」をいくつも順番に行う（エラーの処理、怪しいアクセスを止める、フォームのなりすまし防止など）。 | A |

### src/Controller フォルダ（D チーム）

**ひとことで：「どのデータを使って、どの画面を出すか」を決めるまとめ役。**

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `AppController.php` | **すべての Controller の「親」**。ここに書いたことは、全部の Controller で使える。今は「保存しました」のような、1 回だけ出るメッセージ（Flash）の機能を入れている。全体に影響するので、変えるときは A に相談する。 | D |
| `PagesController.php` | `templates/Pages/` にある画面を、そのまま表示するだけの Controller。トップページを出しているのはこれ。 | D |
| `ErrorController.php` | 「ページが見つかりません」などのエラーが起きたときに出番になる Controller。 | 👀 |
| `Component/` | いろいろな Controller で使い回したい機能を入れるフォルダ。今は空っぽ。 | D |

> 新しく Controller を作るときは、名前を `○○Controller.php` にします（例：`UsersController.php`）。

### src/Model フォルダ（B チーム）

**ひとことで：データベースとやりとりする係。**
今はすべて空っぽです。F チームがデータベースに表を作ったら、B チームが Bake を使って自動でファイルを作れます。

| フォルダ | 何を入れる？ | 担当 |
| --- | --- | --- |
| `Table/` | **表全体**をあつかうファイル。「データを探す」「保存する」「入力のチェック（空欄はダメ、など）」を書く。例：`UsersTable.php` | B |
| `Entity/` | **データ 1 件分**をあつかうファイル。例：会員 1 人分 = `User.php` | B |
| `Behavior/` | いろいろな Table で使い回したい機能を入れる場所。 | B |

> たとえると、`Table` は「名簿」全体、`Entity` は名簿の「1 行」です。
> **F チームと B チームのちがい**：F は「名簿の用紙（表）」を作り、B は「名簿に書きこんだり読んだりするプログラム」を作ります。

### src/View フォルダ（C チーム）

画面を作るときの「土台」になるプログラムです。画面そのもの（HTML）は `templates/` フォルダにあります。

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `AppView.php` | **すべての画面の「親」**。全部の画面で使いたい便利な道具（Helper）があれば、ここに書く。 | C |
| `AjaxView.php` | ページ全体を読み直さずに、一部分だけを入れかえるとき（Ajax）に使う。 | 👀 |
| `Helper/` | 画面で使い回せる便利な道具を入れるフォルダ。今は空っぽ。 | C |
| `Cell/` | 「お知らせ欄」のように、いろいろな画面に置ける小さなパーツを入れるフォルダ。今は空っぽ。 | C |

### その他のフォルダ

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `Middleware/HostHeaderMiddleware.php` | 本番で公開したときに、ニセのアドレスからのアクセスをはじく「警備員」。開発中は何もしない。 | A |
| `Console/Installer.php` | 最初の準備（`composer install`）のときに 1 回だけ自動で動く。`app_local.php` や、必要なフォルダを作ってくれる。 | 🚫 |

## 7. templates フォルダ（画面）

**ひとことで：ブラウザに表示される画面（HTML）が入っている場所。C チームがメインでさわります。**
見た目に関わる部分は E チームと協力します。

### templates/layout フォルダ（画面の「外わく」）

ページの上のメニューや下の部分など、**どのページでも同じ部分**です。
各ページの中身は、この「外わく」の中にはめこまれて表示されます。

```text
=============================
  上のメニュー     ← layout（外わく）
-----------------------------

  ページの中身     ← templates/○○/△△.php

-----------------------------
  下の部分         ← layout（外わく）
=============================
```

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `default.php` | ふつうのページの外わく。CSS の読み込みもここでしている。 | C・E |
| `error.php` | エラーページの外わく。 | C・E |
| `ajax.php` | Ajax 用。外わくなしで、中身だけを出す。 | 👀 |
| `email/html/default.php` | 見た目つきメールの外わく。 | C |
| `email/text/default.php` | 文字だけのメールの外わく。 | C |

### ページの中身

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `Pages/home.php` | 今のトップページ（CakePHP の最初の画面）。データベースにつながっているかなどを確認できる。あとで自分たちのトップページに作りかえる。 | C |
| `Error/error400.php` | 「ページが見つかりません」などのエラー画面。 | C |
| `Error/error500.php` | 「サーバーでエラーが起きました」のエラー画面。開発中は、エラーの原因がくわしく表示される。 | C |

> **新しいページを作るときのルール**
> `templates/Controller の名前/処理の名前.php` に作ります。
> 例：`UsersController` の `index` → `templates/Users/index.php`
> Controller の名前と処理の名前は D チームが決めるので、C チームは D チームと相談しながら作ります。

### templates/element フォルダ（使い回せるパーツ）

いろいろなページに何度も出てくる、小さな部品です。

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `flash/success.php` | 成功したときのメッセージ（例：「保存しました」）の見た目。 | C・E |
| `flash/error.php` | 失敗したときのメッセージ（例：「保存できませんでした」）の見た目。 | C・E |
| `flash/info.php` | お知らせメッセージの見た目。 | C・E |
| `flash/warning.php` | 注意メッセージの見た目。 | C・E |
| `flash/default.php` | 上のどれにもあてはまらないメッセージの見た目。 | C・E |

### その他

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `email/html/default.php` | 見た目つきメールの本文の見本。 | C |
| `email/text/default.php` | 文字だけのメールの本文の見本。 | C |
| `cell/` | `src/View/Cell/` のパーツの画面を入れるフォルダ。今は空っぽ。 | C |

## 8. webroot フォルダ（CSS・画像など）

**ひとことで：ブラウザから直接見られるファイルを置く場所。E チームがメインでさわります。**

> ⚠️ ここに置いたファイルは、URL を打てば**だれでも見られます**。
> パスワードなど、見られて困るものは絶対に置かないでください。

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `index.php` | **アプリの本当の「玄関」**。どのページを開いても、まずここを通る。 | 🚫 |
| `.htaccess` | XAMPP（Apache）への指示書。`/users/add` のような URL でも、ちゃんと玄関（`index.php`）に案内する。 | 🚫 |
| `favicon.ico` | ブラウザのタブに出る小さなアイコン。自分たちのアイコンに変えてもよい。 | E |

### webroot/css フォルダ（見た目）

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `normalize.min.css` | ブラウザ（Chrome、Edge など）ごとの見た目のちがいをそろえる。他の人が作ったもの。 | 🚫 |
| `milligram.min.css` | シンプルできれいな見た目にしてくれる。他の人が作ったもの。 | 🚫 |
| `fonts.css` | `font` フォルダの文字のデザイン（フォント）を使えるようにする。 | E |
| `cake.css` | CakePHP の最初から付いている見た目。 | 👀 |

## 9. tests フォルダ（自動チェック）

**ひとことで：「アプリがちゃんと動くか」を、人の代わりに自動でチェックするプログラム。G チームの担当です。**

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `bootstrap.php` | チェックを始める前の準備。チェック用のデータベースを用意する。 | G |
| `schema.sql` | チェック用のデータベースの表を書く場所。今は使っていない。 | 👀 |
| `TestCase/ApplicationTest.php` | `src/Application.php` がちゃんと動くかのチェック。 | G |

## 10. bin フォルダ（コマンド）

**ひとことで：Git Bash（黒い画面）で CakePHP に命令するためのファイル。**

| ファイル | 何をするもの？ | 担当 |
| --- | --- | --- |
| `cake` | Git Bash で `bin/cake ○○` と打つと、CakePHP に命令できる。 | 🚫 |
| `cake.bat` | `cake` の Windows のコマンドプロンプト版。 | 🚫 |
| `cake.php` | `cake` と `cake.bat` が中で使っているファイル。 | 🚫 |
| `bash_completion.sh` | コマンドを途中まで打って Tab キーを押すと、残りを自動で入力してくれる機能。 | 🚫 |

よく使う命令の例：

| 打つコマンド | 何が起きる？ | 使うチーム |
| --- | --- | --- |
| `bin/cake bake migration CreateUsers` | 「会員の表を作る」ためのファイルを自動で作る | F |
| `bin/cake migrations migrate` | データベースの表を最新の状態にする | 全員 |
| `bin/cake bake model Users` | `UsersTable.php` と `User.php` を自動で作る | B |
| `bin/cake bake controller Users` | `UsersController.php` を自動で作る | D |
| `bin/cake bake template Users` | `templates/Users/` の画面を自動で作る | C |
| `composer test` | 自動チェック（テスト）を実行する | G |

> `bin/cake migrations migrate` は、F チームが表を変えたあと、**全員が自分のパソコンで実行**します。
> 実行しないと、自分のパソコンのデータベースだけ古いままになってしまいます。

## 12. 自動で作られるフォルダ

ここにあるフォルダは、パソコンの中で自動で作られます。GitHub には送られません。

| フォルダ | 何が入っている？ | 担当 |
| --- | --- | --- |

## 13. 中身が空の「.gitkeep」ってなに？

Git には「**空っぽのフォルダは記録できない**」というルールがあります。
そこで、空っぽのフォルダにも GitHub に送れるように、中身が空のファイルを 1 つ入れています。それが `.gitkeep` です。

フォルダにファイルを作ったあとは、`.gitkeep` は消しても残してもどちらでも大丈夫です。
